## 行为约束与实施顺序

1. 先增加回归：容量自动接入、忽略旧手填值、无效/过期/设备隔离、容量变化清窗口、134Ah seed 与其他容量 legacy；首页旧偏好迁移、保留槽位自定义、替换保存/取消/重启。
2. 续航只使用当前有效 BMS 总容量和剩余 Ah，不手填、不硬编码134Ah；缺失/无效/过期显示明确状态。窗口恢复附带容量校验，避免不同容量证据混用。
3. 删除手动容量输入与冗余容量重置，保留窗口/刷新、清除窗口和本地导出；不扩展学习、隐私或 BLE 写入。
4. 首页仅保留槽位式布局；旧十卡片只作解码迁移兼容，现有合法自定义槽位保留。移除模式开关与全局编辑态；参数通过设置中的原生导航替换，首页仍为驾驶只读页面。
5. 运行静态合同检查与 diff 检查，检查 Swift 测试覆盖。Windows 无 Xcode 时不声称 Swift 编译、XCTest/XCUITest 或真机通过，不自动提交/推送/部署。
