# 电池与控制器分离实施说明

## 已确认产品行为

- 五个固定 Tab：仪表盘、电池、控制器、行程、设置。
- 电池只显示 BMS 数据，控制器只显示控制器数据。扫描、连接、断开、忘记在设置 → 蓝牙设备中管理。
- 名称过滤默认独立开启：电池 ant、控制器 apt，大小写不敏感；FFE0 不绕过名称过滤。排障可分别关闭名称过滤。
- 名称只是候选筛选；保存上次设备须等到对应协议的有效帧，不因连接/Notify 成功就确定设备角色。
- 自动连接默认开启。启动和真正从后台回到前台，每个角色各有一次有界尝试；设备不在附近/未授权不保证连接成功。
- 手动断开仅抑制本次进程自动连接，保留记忆；重启 App 仍按开关尝试。手动重试可恢复自动连接意愿。
- 忘记设备断开并删除该角色 UUID/名称，不删除历史、容量、行程或其他角色记忆。
- 控制器记录/历史/导出放二级页面，可从控制器 Tab 或设置进入；RPM 测试保持 RPM-only。
- 同一 UUID 不允许同时被电池和控制器会话占用；旧会话退出前保持占用，防止晚到回调污染新会话。
- 不增加蓝牙后台运行权限，不新增硬件控制/参数写入，不引入第三方 UI 依赖。

## 实施与验证顺序

1. 增加纯领域名称过滤、前台连接策略及 UUID 角色占用测试，锁定上述边界。
2. 两个服务分别实现过滤、记忆、忘记、有界重连及身份隔离，保留原分帧/记录契约。
3. 新蓝牙设置页接入唯一设置存储；驾驶设置草稿不得覆盖蓝牙页后来保存的连接偏好。
4. 数据页拆分；无数据/过期/断开显示 --，不伪装真实零值。
5. 更新五 Tab 和快捷入口、设计主约束、UI 测试与静态契约检查。
6. 运行可用检查；明确区分 Windows 静态检查、Swift/Xcode/CI 与真实 iPhone/BMS/控制器验收。

## 验收清单

- 两种名称列表互不混入；已记忆 UUID 改名仍按 UUID 自动尝试，不改连同名设备。
- 同时连接两台不同设备、各自断开/忘记不影响另一台。
- 权限等待、蓝牙关、记忆不存在、retrieve 失败、定向扫描超时有反馈，无无限重试。
- 手动断开后 background → active 不抢连；重启保留记忆；忘记后不连接。
- 旧回调不影响新会话，协议无效不更新记忆，数据过期/断开不显示旧数据为实时。
- 浅色/深色、Dynamic Type、VoiceOver、横屏/小屏，仍只有五个系统 Tab。
